# Past Paper Question Audit — Level 100 to 300 Courses

**Audit time:** 2026-11-07 22:55 E. Africa Standard Time  
**Scope:** Every course whose code number falls in the 100, 200 or 300 band (for example SMA 330 is a 300-level course) and which has at least one past paper or one extracted question. Level 400 courses are deliberately excluded and will be audited separately.
**Method:** Read-only database audit. For each course the report lists every active topic with the number of questions that are currently learner-visible, broken down by question type, together with the questions that are hidden because they are flagged or still pending verification. No question, paper or cache record was modified.

## How to read this report

- **VISIBLE n of m** — n questions are shown to learners. The bracket separates them into auth (authentic past-paper), adapt (adapted) and gen (generated variants). A question counts as visible when its verification status is verified, auto_validated or reconstructed *and* its paper is published.
- **HIDDEN** — a question exists for the topic but none of it reaches a learner, because every question is flagged for correction or still pending verification.
- **NO QUESTIONS** — the topic has no extracted question at all.
- **without solution** — the question is visible but its worked solution is empty, so a learner sees the problem with nothing to mark their attempt against.
- **not mapped to any topic** — the question exists on a published paper but was never attributed to a syllabus topic, so it does not appear under any topic page.

## Notes on interpretation

A question that is flagged has been extracted but failed the automatic consistency checks, so it is withheld rather than shown. A pending question has never been through verification. Both are recoverable, but by different work: a flagged question needs its statement or solution corrected, while a pending question needs to be verified from the source paper.

Questions that are not mapped to any topic still display on the paper view, but they never appear under a topic, so a learner revising a specific topic will not find them. Mapping them is usually the cheapest improvement available, because no new extraction is required.

This audit describes the application's own visibility rules, not a browser-by-browser review of each paper page. It also does not judge whether an individual question is mathematically correct; it reports only the state the app has recorded.
